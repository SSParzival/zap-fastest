ZapFastest 0.34.0 hardens the features integrated from ZapFast v0.21 in 0.33.0 and gives new packages, installers and portable downloads a consistent ZapFastest identity. Existing linked accounts keep their sessions, encrypted archives and settings.

## New

- **Manage blocked contacts in each account.** Block and unblock from contact menus or Settings. The list is refreshed after an uncertain request and when the connection returns.
- **Export a chat with its downloaded attachments.** Save locally archived messages as readable text, or a ZIP containing `_chat.txt` and media. Large attachments are copied in small chunks. Missing history and files are reported rather than downloaded, and locked chats cannot be exported.
- **Received broadcast messages appear with their sender.** Existing broadcast-list rows are migrated transactionally, preserving local media, polls, reactions and deletion barriers. This does not add a broadcast roster editor or automated sending.
- **Preview outgoing links with the phone's privacy choice.** Previews stay off while the phone's setting is unknown. Dismissing a card cancels its pending fetch. Proxied connections skip previews because the remote resolver cannot be checked for private addresses.
- **Keep listening while changing chats.** The persistent voice bar offers play, pause, stop and navigation to the originating message. Switching accounts stops playback to preserve account isolation.
- **Review attachments before sending.** See staged photos at full size and use the existing crop and rotation tools.
- **Receive animated Lottie stickers.** Bounded `.was` animations render locally. Sending, favoriting and adding these stickers to packs remain unsupported.

These features originated in the [ZapFast v0.21 integration](https://github.com/SSParzival/zap-fastest/commit/5f0e37accbff5248240a0a98a9906d19fd18ceaf); the fixes below are part of this release.

## Fixed

- **Private networks stay out of link previews.** Proxy configurations cannot bypass the guarded DNS resolver. Redirects and downloaded metadata remain bounded.
- **Privacy refusals take effect even if storage fails.** Disable events cancel pending preview requests; logout, account switching and app lock also cancel relevant work. Unrecognized stored privacy values keep previews off.
- **Exports from another account stay out of your current screen.** A hidden account's completion clears only its own progress and cannot reveal its export path in a toast or close another account's dialog.
- **Portable attachment filenames.** ZIP entries reject traversal sequences, separators and control characters and cap UTF-8 byte length as well as character count.
- **Sticker payloads have stricter limits.** JSON complexity, composition expansion, ancestry and parent cycles are checked before rendering. Raster image assets, expressions and repeaters are refused until their renderer work can be bounded safely.
- **Closed previews release their textures.** Animation textures are dropped after a frame that no longer draws them, including when the last sticker closes. Parked pasted-image drafts retain their source bytes without retaining GPU textures.
- **Paused audio resumes from its saved clock.** The output device is released immediately on pause; resuming avoids a lossy fraction conversion.
- **One name across new releases.** Application text uses ZapFastest and new binaries, recipes, installer resources and release assets use `zap-fastest`. Stable storage, keyring, Flatpak and installer identities, upstream credits and published historical evidence remain compatible.

## Verification

The final Linux unit run passed 2098 tests with zero failures (15 hardware/manual tests ignored). Default and all-feature target suites, formatting, type checking, Clippy with `-D warnings`, rustdoc, dependency-source checks, the three packaging scripts and the release build all passed.

The Linux build, lint, test and packaging results, command exit codes and SHA-256 input hashes are recorded in `docs/verification/release-0.34.0.json`. The audit scope and limitations are in `docs/verification/audit-0.34.0.md`. Windows and macOS runtime acceptance and live WhatsApp/device synchronization require separate attended checks.
